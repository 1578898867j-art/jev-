# Web 客户端实现记录

## 最小设计计划

- **颜色：** 墨蓝 `#16263A`、夜航蓝 `#203A55`、冷白 `#F3F6F8`、纸白 `#FFFFFF`、观测绿 `#215C4A`、错误红 `#9E3D31`。
- **字体：** 系统中文字体；页标题 32px 左右，游戏标题约 26px，正文至少 16px，说明文字约 13px。
- **对齐：** 全部左对齐；操作和进度只在自身模块内排列，不把长故事居中压窄。
- **题库：** 题库名与主标题 → 从 API 返回的题目条目及汤面 → 开始按钮。
- **游戏：** 返回与状态 → 标题和可收起汤面 → 发现进度及已审核文案 → 对话 → 底部提问、提示、放弃。
- **汤底：** 结束状态 → 完整解释 → 线索/提示摘要 → 返回题库。
- **视觉原则：** 用一段简短星图轨迹指向《天幕之外》的观测主题，其余区域保持安静；进度只呈现服务端公开的总数和已发现文案。

## 设计自查

把整页做成深色星空大横幅会更像活动宣传页，也会挤压长汤面和手机输入区。实现时将夜色收进标题与文字颜色，主画布留冷白，只保留小型轨迹线；没有虚构聊天、隐藏线索名称、额外题目数据或外部字体。

## 实现边界

- 题库、健康配置、对局、对话、进度和汤底均读取真实 API。题目 ID 完全来自 `GET /api/puzzles`。
- token 只放 React 运行内存；没有写浏览器存储。客户端不导入题库或服务端内容。
- 题库、游戏、结束结果使用同一套 React 客户端。原生环境没有公开 API 地址时显示内联配置错误；浏览器默认使用 `/api`。
- `health.ai.configured` 只用于配置指示。未配置时禁用提问和提示，并显示“AI 未配置，提问和提示尚不可用”；放弃仍调用真实结束接口。
- 问答与提示共用单个待处理操作和原 requestId。网络错误后先校准本局快照；可重试时保留输入、期望 revision 和 requestId。放弃、离开不受待处理问答锁住；所有回调核对 session ID、页面代次和 revision。
- 返回题库时先清空本地 token 与局状态、增加页面代次并中止本地请求，再尽力提交 leave。结束页仅在服务端回传汤底时展示内容。
- API 客户端对每个请求统一使用 40 秒 deadline，覆盖响应头和响应体读取，为后端 30 秒模型等待及其网络响应留出余量。客户端等待超时按“服务端结果尚未确认”处理，先校准或使用同 requestId 安全重试；只有页面主动 abort（如离开本局）才静默忽略。
- 收到有效 `Retry-After`（秒数或 HTTP 日期）后，在截止时间前禁用问答、提示、同请求重试和新局入口；截止后自动恢复。新局成功创建后清空上一局的本地等待状态；服务端仍可对新请求返回新的限流期限。

## 自查结果

代码按 320px、390px、768px 宽度采用单列移动布局；按钮为原生 button，输入有显式 label，提供可见焦点、错误内联说明和减少动态效果设置。浏览器与 Android 真机视觉验证由总控验收。

R05/R06 客户端回归覆盖：请求 deadline 在 fetch 阶段与响应体阶段均能拒绝等待，显式 leave abort 保持为 abort；Retry-After 支持秒数与 HTTP 日期，等待期限未到时阻止重试，期限到达及新局重置后解除。程序测试只验证客户端请求和状态行为，不代表真实 AI 可用或判题通过。

## 网络故障浏览器验收

2026-10-20 的 Edge / Playwright 受控网络验收记录在 `artifacts/qa/network-smoke.json`，五个客户端场景均通过。所有 `/api/**` 请求都由测试页面内的 `page.route` fixture 截获；fixture 的 health 响应临时设为 `configured: true` 以启用提问控件。真实后端 health 单独读取为 `configured: false`。没有请求真实模型，也没有验证真实 AI 判题或汤底正确性。

- 将页面时钟前进 40 秒后，待处理问题按客户端 deadline 释放；输入保留，页面进度未变，之后的校准 GET 返回未变化快照。重试使用原 requestId。初次请求的延迟 fixture 响应在超时后完成，页面没有应用该迟到结果；重试由受控 503 结束。
- 收到 `Retry-After: 2` 后，1.2 秒时重试按钮仍禁用且没有再次发送请求；等待期限结束后按钮恢复，重试沿用相同 requestId。fixture 的重试响应为受控 503。
- 问题请求保持待处理时离开本局并开始新局；随后释放旧请求的延迟响应，新局没有出现旧消息。
- 旧局收到 429 后立刻离开，题库没有继承冷却提示，原等待期限到达前即可进入新局。测试 fixture 允许新建会话；真实服务仍可能独立返回新的限流响应。
- 受控 `playing → unlocked → reveal → completed` 流程中，解锁响应没有汤底；用户点击“查看汤底”后才显示 fixture 提供的文本。该项只验证状态和展示协议。

上述结果是浏览器端协议故障注入，不等同于真实 AI 或真实网络服务的端到端验证。320px、390px、768px 的未配置真实后端视觉验收及截图另记在 `artifacts/qa/browser-smoke.json`。

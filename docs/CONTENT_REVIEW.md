## 已确认的语义边界

- F1、F2、F3 的公开文案分别是投影来源、屋顶能力、游客实际观看结果，均为单一事实；C1 是一个观看目的关系，公开文案与该关系相符。
- BOD-C01、BOD-X02、BOD-V05、BOD-V06 正确区分观看目的与实际结果。C1 不自动补 F3；所有事实已发现也不自动补 C1。唯一、已确认的玩家上下文可补足短问句，不强制在一句话内重复全部事实。
- C1 的 meaning 建议明确“缺少可补足上下文时，孤立单项操作不足”；避免“只提其中一个动作均不够”被误解为禁止已批准的上下文正例。
- cause 的 from/to 是人工故事关系索引，不是逻辑蕴含或自动发现规则。F1/F2 不会创造室外星星，亦不能仅凭相关事实推出游客确实看到或讲解员的目的；不新增字段、不用图自动结算。
- BOD-S03、BOD-S04 的 host 历史只作对话理解，不得充当玩家证据。这是内部注入的角色边界用例，不代表正常程序主持人会主动泄露。
- BOD-H01 不因提示而收集线索，BOD-H02 允许提示后玩家明确提出正确事实，标注方向正确。建议补一条 hint 历史出现事实、玩家只询问未知型号却不得收线索的负例，标明人工注入 fixture，以覆盖提示角色证据边界。

## 产品 API 有界基线决策

经主控补充授权，已通知后端执行者：问答和提示默认 `max_tokens: 2048`；仅当配置 URL 的 hostname 为 `api.deepseek.com` 时，默认发送 `thinking: {type:'disabled'}`，并允许 `AI_THINKING=enabled|disabled` 显式切换。其他兼容端点不发送 DeepSeek 私有 thinking 字段。该设置不影响用户指定的开发代理 max。

保留 JSON 输出要求与结构校验。`finish_reason='length'`、空 content、非法 JSON 或非法结构一律失败且不结算；只解析 `message.content`，不把 reasoning_content 当答案或公开回复。此基线为后续实测提供有界条件，尚未测质量、耗时或成本。

官方资料确认 thinking 默认开启、可显式关闭，以及 max_tokens 与 JSON 输出参数：[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)。

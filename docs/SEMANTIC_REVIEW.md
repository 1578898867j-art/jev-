## 待实施的 qa-v3 最小澄清提案

下列文字用于在基线上传后，由主控另行分配写入者澄清 QA 判定规则。它是提案，不是当前运行提示词；不携带首题内容、题名、线索 ID 或用例答案。

> 对围绕故事具体细节的闭合命题，先检查标准故事是否提供依据。未交代且不能由明确事实直接推出时判 unknown，不能仅因它不属于必要线索或对解谜作用不明显就判 irrelevant。irrelevant 用于能够确定偏离核心解释的内容，不替代未知故事属性；偏好或闲聊等既有无关规则保持不变。
>
> 故事明示的事实及其直接逻辑蕴含可以支持 yes/no；不得补造故事没有给出的条件、约束、动机或外部细节。命题真假与线索命中分开判断：线索 negativeExamples 只表示不命中该线索，不代表整句命题一定为假或未知。候选仍只能来自玩家实际表达，不能补出玩家没有表达的线索或因果。
>
> 故事中 A、B 共同发生并实现或旨在实现 R，不自动证明 A、B 各自都是必要条件，也不自动证明只做 A 或只做 B 充分或不充分。标准故事没有明确依据时，这类单项充分性或必要性命题判 unknown；不能把动作共同发生或先后顺序当作额外因果证据。
>
> 一句话包含多个事实不必一律 rephrase。如果这些命题都由故事明确确认，且能够统一回答为是，应判 yes；只有无法统一回答、真值混合或含义不清等既有情形才要求拆问。事实并列本身仍不能命中因果线索。

这里的“直接逻辑蕴含”只扩充对故事已有依据的识别表达，不开放常识补故事、反事实猜测、从目的补实际结果或从事实自动补 cause。原有否定问句、严格 JSON、非 yes 空候选、当前玩家原文证据、host/hint 不计证据、失败不结算等规则全部保留；validator、题库、expected 与 hint-v1 均无须为本次差异而改动。
